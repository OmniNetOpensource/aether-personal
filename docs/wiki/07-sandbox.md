## 环境与操控工具

Linux 环境提供运行程序的地方，Agent 还需要工具来操控该环境。终端工具负责启动命令、读取输出和停止进程。文件工具负责读写文件；面向用户的附件交付接口尚未实现。浏览器工具负责读取页面和执行操作。桌面工具负责截图、鼠标与键盘输入，让 Agent 能观察图形界面、操作软件并检查结果。

运行时仍由 Go 后端调用模型并调度 Agent。沙盒承担软件与进程的执行，工具结果回到 Agent 上下文中。本地接入 OpenSandbox `release-1.1.0` 的 Docker 运行时；维护者云环境选择阿里云 FC Agent Sandbox 二代运行时，接入与验证边界见下文。

## 持久化与暂停 `开发中`

2026-10-23，用户确认工作环境长期保留，空闲时暂停，下次恢复继续使用。用户原话为：

> 长期保留，空闲时暂停，下次继续用

文件、已安装软件、用户配置和浏览器登录状态保存在用户的工作环境中，不随任务完成或空闲暂停而清空。暂停后恢复原工作环境，避免每次重新安装软件、准备文件和登录网站。外部网站仍可使登录凭证过期或要求重新验证，保存浏览器状态不能保证登录永不过期。

选择理由：Agent 需要延续之前的工作，同时在空闲期间释放计算资源。长期保留会继续占用存储空间，暂停不等于删除环境。

空闲以工作状态判断。正在执行的任务、后台命令或待处理的操作不能仅因用户没有发消息而被视为空闲。满足空闲条件并经过空闲窗口后暂停，后续需要使用环境时自动恢复。具体空闲时长由技术实现配置。

技术选型优先满足磁盘与内存状态的保存和恢复，让桌面程序与进程能从暂停位置继续。暂停期间程序不继续计算，恢复后需要重建已经失效的网络连接。持久化文件还需要独立的可靠存储，不能把进程暂停等同于数据备份。

OpenSandbox 的暂停语义取决于底层运行时。普通 Kubernetes rootfs 快照保存文件系统，不保存进程内存。Fast Sandbox 的 Firecracker 检查点包含 rootfs、虚拟机状态与内存，才具备恢复运行现场所需的状态。以上来自官方 [暂停与恢复说明](https://github.com/opensandbox-group/OpenSandbox/blob/main/docs/guides/pause-resume.md) 和 [Fast Sandbox 检查点说明](https://github.com/opensandbox-group/OpenSandbox/blob/main/docs/architecture/fast-sandbox/checkpoints.md)，尚未在本项目部署验证。

## 聊天页面实时桌面（2026-10-26）

用户要求实时观看沙盒桌面，并选择“聊天页面，供用户查看自己的桌面”。入口位于聊天页顶部的“查看桌面”。宽屏将桌面放在聊天右侧，窄屏覆盖聊天并提供关闭按钮。选择理由是让用户在当前对话中看到 Agent 操作电脑的过程。

Web 宿主使用固定版本的 noVNC 展示画面，ReactLynx 通过 `AetherHost.openDesktop` 打开面板。后端从聊天会话推导用户，再读取该用户的 `user_sandboxes` 映射。客户端不提交沙盒 ID 或目标端口，也不持有 OpenSandbox 管理密钥。

`GET /sandbox` 使用现有 Bearer 会话，返回供应商当前状态和观察时间。`GET /sandbox/desktop` 升级 WebSocket，第一帧验证聊天令牌，再通过服务端认证的固定 6080 端口连接。令牌不放在 URL 中。缺少环境时只显示尚未创建，暂停时只显示暂停；观看不会创建、恢复、替换环境或更新空闲活动时间。运行中的环境自动连接，正常空闲暂停规则继续生效。

第一版只读。Go 后端验证 RFB 3.8 握手，只转发画面格式、编码、画面更新请求、连续更新和同步确认。键盘、鼠标、调整远端分辨率、电源与未知指令会关闭连接；有界的剪贴板消息被丢弃。限制发生在服务端，不依赖 noVNC 的 `viewOnly` 标记。协议按连续字节流解析，允许 WebSocket 分片与合并，但完整校验一条请求后才转发。

关闭面板、退出登录或隐藏浏览器标签页会断开观看。后端每五秒检查会话、沙盒状态和归属映射，失效时关闭连接；单次连接最长 30 分钟，面板可重新连接。同一后端实例中，每个用户同时保留一个观看连接。画面不写入消息、数据库或服务日志。部署反向代理时，`/sandbox/desktop` 需要转发 WebSocket Upgrade。

本地已用 In-App Browser 验证真实桌面、动态新增终端窗口、关闭重连和暂停提示；确认打开暂停环境不会恢复它。另一个本地账号不能通过指定查询 ID 选择现有用户的环境。直接 WebSocket 检查覆盖分片握手、合并请求、剪贴板丢弃，以及键盘、鼠标和控制指令拒绝。Go 构建与 vet、TypeScript 检查及 Web 和 Lynx bundle 构建通过，没有新增测试文件。原生平台仍需要宿主实现 `openDesktop`，尚未完成设备验收。

## 实现约束

执行命令和桌面操作会改变外部状态。运行时先把完整模型回复写入 `steps.model_reply`，再按 `(step_id, tool_call_id)` 记录 `sandbox_operations`，之后才调用外部接口。重启后使用原回复与原调用 ID：已有回执直接复用，有命令 ID 就查询；没有 ID 且可能已提交的修改操作标为 `unknown`，不自动重做。该机制避免盲目重放，不能保证外部操作恰好执行一次。

Agent 运行期限、单条命令期限与沙盒生命周期需要分别管理。后端停止等待或取消网络请求，不代表沙盒进程已经终止。

Main 与 Subagent 使用 PostgreSQL 会话锁 `sandbox:<user_id>` 协调操控。同一用户一次由一个 Agent 控制沙盒，观察与后续动作之间保留控制权；其他 Agent 持久化原回复后延迟两秒再调度，不重新生成工具调用。持有者派发或发送后续任务时释放控制权，连续持有最多 15 分钟后让出。不同用户的控制权互不影响。文件任务使用独立路径以免逻辑上互相覆盖。


## 当前接入 `开发中`

首次使用沙盒工具时创建环境，用户注册时不提前占用计算资源。数据库 `user_sandboxes.user_id` 为主键，保存稳定的分配 ID 与 OpenSandbox ID。创建请求结果不明时按分配 ID 查询并接回已有环境，绝不直接创建第二台；原环境丢失时保留映射并报错，不用空环境替代用户资料。

| 工具 | 当前行为 |
| --- | --- |
| `run_command` | 后台启动，返回命令 ID；默认期限 300 秒，最多 3600 秒 |
| `get_command` / `stop_command` | 只接受该用户拥有的命令 ID；查询退出码与最多 32 KiB 输出，或请求停止并确认状态 |
| `read_file` / `write_file` | 绝对路径的 UTF-8 文件，单次最多 2 MiB；二进制处理使用命令 |

截图作为 `name=sandbox_observation` 的内部多模态消息送给模型，不作为人的新请求，也不展示在聊天列表。每次模型请求只保留最近四张截图，更早的图片替换为文字提示；数据库原记录仍保留，后续需补充存储配额与保留策略。模型必须支持图片输入及工具调用。

浏览器可通过桌面操作，也可在沙盒内用 Playwright 连接 `127.0.0.1:9222` 的 CDP。持久浏览器目录为 `/home/desktop/.config/aether/chromium`，工作目录为 `/home/desktop/workspace`。Python 文件处理环境预装 pandas、openpyxl、python-docx、pypdf、Pillow；命令行另有 Git、curl、jq、zip 和 PDF 工具。当前开发环境使用非 root 的 desktop 用户，允许安装 Python/npm 等用户环境软件；Docker 的 no-new-privileges 会阻止 sudo 提权。系统软件通过镜像配置，Agent 任意安装系统软件与管理 Linux 系统的完整权限尚未实现，不能宣称已具备全部 Linux 能力。

开启方式见 [开发环境说明](../../infra/sandbox/README.md)。后端只从环境变量读取 `SANDBOX_URL`、`SANDBOX_API_KEY`、`SANDBOX_IMAGE`、`SANDBOX_IDLE_SECONDS`。未配置 URL 时不注册这些工具。管理密钥只在后端与可信管理服务之间使用，不提供给模型和沙盒。

### 空闲判断

每 30 秒检查一次。默认空闲窗口 300 秒，可配置为 30–86400 秒。没有未完成 Agent 步骤、待读消息、运行中的 Subagent，且没有运行中或结果不明的沙盒操作，才允许暂停；完成后台命令后重新开始计算空闲窗口。暂停前持有同一用户的沙盒控制锁并再次检查工作状态。后续工具调用查询真实状态并恢复原 ID，等待执行服务可达后才提交命令。

启动脚本中的桌面、VNC、浏览器属于环境基础服务，不作为用户后台工作阻止暂停。模型提示词禁止使用 `nohup`、shell `&` 等方式脱离命令跟踪；当前尚无内核级限制来防止所有自行脱离的子进程，因此部署者不能把命令登记当作完整进程审计。

### 验证与边界

本地已使用独立 PostgreSQL 数据库、真实 OpenSandbox 与真实模型验证命令退出码、文件写入与回读、桌面截图、浏览器打开网页、两用户分配不同环境，以及 Main 与两个 Subagent 共用同一用户的环境。后端重启后仍使用原环境 ID，原文件保留；空闲后自动进入 Paused，下一次工具调用恢复。另修复了供应商在镜像标签更新后查询旧环境返回 500 的问题，管理服务重建后原运行环境与已暂停环境均仍可查询，见开发环境说明。还验证了缓存回复等待控制权时延迟调度、结果不明的写入不重放、缺失环境保留原映射，以及恢复旧终止回复后仍处理新消息。独立屏幕挑战中，模型仅凭截图正确读出未放入上下文的随机六位数。已有运行时 PostgreSQL 集成检查、构建与静态检查通过；没有新增测试文件。

Docker 开发模式的暂停是 cgroup 冻结：保留当前宿主机上的进程内存，不释放全部内存；已验证 shell 变量与 PID 在暂停恢复后保持。它不能证明宿主机重启后恢复进程，也没有独立的持久磁盘备份。当前 Apple Silicon 开发机没有可用的嵌套 KVM，生产的虚拟机检查点需在支持 KVM 的 Linux 主机上另行验收。

完整 Linux 能力与生产部署尚缺：沙盒内系统管理权限、虚拟机级租户隔离、租户网络策略、磁盘与内存检查点及备份恢复、容量与用量控制、环境缺失或不明操作的运维处理。当前开发 Docker 配置不能作为企业多租户生产部署。文件附件下载 API 与人工接管尚未实现。

```dotenv

SANDBOX_URL=https://api.ap-southeast-1.e2b.fc.aliyuncs.com
SANDBOX_DOMAIN=ap-southeast-1.e2b.fc.aliyuncs.com
SANDBOX_API_KEY=<服务端 Team API Key>
SANDBOX_IMAGE=<已准备好的二代 desktop 模板 ID>
```

数据库继续保存每用户一个分配 ID，阿里云环境 ID 加 `aliyun:` 前缀，防止切换供应商时误用现有环境。创建结果不明时按分配元数据查找；不会无条件重建。旧 OpenSandbox 映射不能直接迁移到阿里云，缺失或不匹配的环境保留映射并报错。
