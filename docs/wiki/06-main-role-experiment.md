# 06 Main 职责选择与验证

用户在 2026-10-23 希望比较两种架构。当时 A 组保持原有职责：Main 理解需求、分派任务、接收结果并回复用户，搜索和网页读取由 Subagent 执行。B 组保留分派能力，同时允许 Main 使用与 Subagent 相同的 `search`、`fetch_url`。两组的消息权限保持各自角色的现有规则，Subagent 不获得派生更多 Subagent 的能力。

用户确认：A 组“就是现在这样”；实验“就本地用同样一套提示词，然后把结果给我 review 来测试”。最初只做本地对照，没有界面切换或线上流量分组。随后用户明确确认全面采用 B，正式运行时统一允许 Main 直接执行工具，不保留 A 的运行开关。选择来自用户产品决定，不表示小样本已证明 B 普遍更优。

## 控制条件

两组运行同一套用户任务，Main 使用完全相同的实验系统提示词，Subagent 提示词相同。模型、工具定义和服务、并发规则、超时规则保持一致，每项任务的两组历史分别隔离。多轮任务只保留该项任务自身的历史。

实验前的生产提示词明确要求 Main 委派搜索和阅读。实验使用一份共同的中性版本，让它根据可用工具选择直接执行或委派。A 的执行权限仍然只允许委派，B 才能直接执行。报告保留生产提示词、实验提示词及修改说明，避免把实验 A 称为生产提示词完全未变的重放。

## 结果与证据

测试覆盖无需联网的文本任务、指定网页、搜索后阅读、多来源比较、跨平台调研和历史追问。每项任务先各运行一次，交替 A/B 先后顺序，作为用户审阅回答质量的初步样本，不据此判断普遍的性能优劣。

报告保留全部用户可见消息，包括进度回复、最终答案、部分输出和失败。第一条回复不代表任务完成；结束需核对待处理消息、未完成步骤、Subagent 状态和运行中的 Agent。

附带记录 Main 与 Subagent 的实际工具调用、模型请求次数、输入输出 token、返回最后一条用户消息的耗时，以及执行完全停下的耗时。模型费用仅为 OpenRouter 返回的费用，不包括尚无账单数据的搜索和正文提取服务。没有返回的费用记录为未知，不能记为零。

B 组得到工具不代表它使用了工具；报告单独列出 Main 的实际搜索、读取次数。搜索结果、模型采样、供应商状态和本机负载都可能造成单次差异，原始记录用于复核，回答质量由用户 review。

## 当前 B 架构验证入口

项目根目录执行 `make check-research`，使用正式 Main/Subagent 提示词和正常 Runner 重放相同类型任务，不改写提示词、不保留 A 权限分支。模型沿用实际配置，验证请求显式固定温度为 0，并保留这一差异。测试还要求跨平台案例实际派发 Subagent 并收到汇报，避免只证明 Main 直接执行。

命令会调用真实服务并消耗额度。结果默认写入 `docs/experiments/agent-research/<时间>/`，可用绝对路径 `RESEARCH_OUTPUT` 指定。可通过环境变量 `AGENT_RESEARCH_CASE` 只选一项。每项使用独立数据库 schema，不写入日常聊天记录，输出完整可见消息、模型请求、工具结果、费用与运行清单；密钥不写入报告。原 A/B 输出及对应源文件快照保留在本地 `docs/experiments/main-role-ab/2026-10-23-initial/`，两类结果都不进入 Git。

## 首轮运行记录

2026-10-23 已完成六类任务、十二次运行，共十四轮输入。核对了 74 次真实模型请求，模型、温度、两组 Main 的实验提示词、Subagent 提示词与各自工具集均符合控制条件。实验数据使用独立 schema，运行后已清理，未写入日常聊天记录。

本轮暴露了共用交付约定的问题：模型有时直接输出正文，没有调用 `send_message`。A 的五轮联网输入只生成进度消息，一轮追问没有可见回复；B 有一轮联网输入没有可见回复。内部正文保留在原始记录中，没有补作已发送答案。模型请求、HTTP 与工具结果均无报错记录，不能以这些计数代替消息交付或回答质量。

权限与记录测试通过，包括 A 拒绝执行、B 实际执行、角色消息限制，以及缺失费用不能当作零。真实对照命令由于两轮没有可见回复而返回非零，仍继续完成并保存全部案例。这是修复前的探索性记录。用户随后选择 B；后续以正式 B 提示词重放任务验证交付，不将提示词和交付修复后的结果称作同条件 A/B 性能比较。

本地结果包含逐项 A/B 可见消息、总览、共同提示词、指标及完整执行记录。回答质量留给用户 review。

## 采用 B 后的真实重放

2026-10-23，使用正式提示词重放六类任务、七轮输入，均收到实质结果。Main 直接搜索和读取、三路 Subagent 派发与回传、多轮追问均已执行。跨平台任务发出两条进度和一条整合结果；三名 Subagent 都回传了消息。

跨平台任务中 Main 有一次直接输出终止正文，运行时追加纠正后成功通过 `send_message` 交付，没有将原正文自动展示。该违规及模型用量保留在步骤中，因此严格重放命令返回非零，案例状态为 `quiescent_with_errors_unscored`。其他五题没有记录 HTTP、工具或步骤错误。不能把本轮写成“全部无错通过”，也不能把这次修复后的 B 重放与历史 A 作性能结论。

结果位于本地 `docs/experiments/agent-research/2026-10-23-b-adopted/`。另外通过 Flutter Web 页面验证 Main 实际调用 Google 搜索、读取官方网页并发出结果，四次模型步骤无错误或未完成项。Go 构建、静态检查、真实隔离 PostgreSQL 与 `-race` 回归通过；十项交付检查覆盖纠正上限、重试计费、重启及新输入不丢失。原生端和线上部署未验收。
