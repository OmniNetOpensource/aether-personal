## 可以观察什么

从用户进入 Main / Subagent，再下钻到每次模型请求：请求及响应模型、结果、HTTP 状态、输入输出 Token、提供方返回的 USD 费用、请求耗时、工具名称和关联执行步骤。支持时间、用户、Agent、模型及结果筛选、游标分页和自动刷新。运行概览保留用户使用情况，用户与 Agent 筛选器仍可使用。列表提供元数据，调用详情可查看实际请求与响应 JSON。请求 JSON 包含发送给模型的消息上下文、工具定义和保留的截图；响应按提供方原文保存，包括错误 JSON。HTTP 认证头与供应商密钥不采集。

## 为什么增加 model_calls

`steps` 是逻辑执行步骤，完成时间包含工具执行、暂停等待和恢复。步骤可能在真正发请求前创建，也可能在重启后继续，不能把它当成准确的 HTTP 次数或模型延迟。

`00006` 新增 `model_calls`：每次准备发出 HTTP 请求前独立写一行，从关联步骤推导用户和 Agent；返回后独立写终态与可空用量。记录成功、HTTP 错误、传输错误、无效响应、中断和进行中。请求成功但之后工具失败时，请求费用仍保留。实际请求模型独立于步骤的旧模型配置记录。

这是应用观察到的请求尝试，不是供应商账单，也不是网络 exactly-once 保证。写入后、真正发送前崩溃可能留下未发送的尝试；取消/崩溃可能已在供应商产生费用。不得把中断解释为免费。

终态写入有独立短超时；写入失败不继续执行工具。调度器也扫描未完成调用的归属，取得对应 Agent 咨询锁后才能把旧的进行中记录标为中断，避免只按时间误伤慢请求。中断记录不填写伪造的请求延迟，旧执行者不能覆盖已恢复的终态。

## 看板导航与请求详情（2026-10-26）

用户要求删除“用户”“Agents”“历史步骤”三个 tab，并在每条模型调用详情中查看请求和响应 JSON。看板只保留“运行概览”“模型调用”“模型配置”。选择理由是集中查看每次实际模型调用及其输入、输出。运行概览中的用户入口改为筛选该用户的模型调用，不再跳转到已删除的页面。

`00010` 为 `model_calls` 增加 `request_body`、`response_body` 和 `response_truncated`。每次请求发送前，把用于该 HTTP 请求的 JSON 请求体与调用日志一起落库；收到响应后，在调用终态写入时保存原始响应正文。每次重试各自记录，保存失败会使当前执行报错。旧日志没有实际载荷，不根据当前提示词或历史消息猜测回填，详情明确显示未记录。

详情按调用 ID 单独加载，不把完整上下文放进列表。请求与有效响应格式化为可选择文本的 JSON。非 JSON 响应显示原始文本；网络失败未收到正文时显示未记录响应。沿用模型客户端的 8 MiB 响应接收上限，超出时保留已接收部分并显示截断提示。管理端代理流式传输详情，完整请求不会受到列表接口 2 MiB 缓冲上限影响。

载荷与调用日志保存在同一条记录，删除用户或步骤时随调用日志级联删除。载荷只通过独立管理会话读取，响应为 no-store。这里会包含业务对话与模型返回内容，取代早期仅展示元数据的范围。

## Agent 运行过程（2026-10-30）

## 统计口径

- 请求延迟包含 HTTP 网络、提供方处理及响应读取/解析，排除后续工具执行与重试退避；不是首 Token 延迟。
- 明确返回的 0 是已知 0；未返回、null 或非法负数为未知，分别显示覆盖数量。费用使用精确 decimal 字符串，币种 USD，不包含搜索费用。
- 工具分布是模型提出的调用名称，不代表实际执行或成功；只允许已知名称，其他归为 `other`。
- 接入前的步骤不伪造回填请求。没有请求日志的已完成/已缓存回复步骤作为历史记录，原 Token/费用单独标注来源未验证，不合并进新采集统计。首个观测时间是第一条调用日志的时间，并非部署时间。
- Agent 的处理中表示调度/执行状态，不能解释为模型正在生成 Token。请求结果和整个步骤结果分别显示。

## 权限与 API

2026-10-26，用户要求：“只需要输入密码就可以进入看板”。看板改用共享管理员密码，不需要邮箱或验证码。选择理由是减少管理入口的登录步骤。聊天继续使用邮箱验证码，其会话与管理会话完全分离。

在本仓库根目录执行 `python3 scripts/set-admin-password.py`，两次输入至少 12 个字符的密码。脚本使用随机 16 字节盐和 PBKDF2-HMAC-SHA256（600,000 次）生成哈希，把带单引号的 `ADMIN_PASSWORD_HASH` 写入未提交的 `backend/.env`。保留引号，避免加载环境变量时把哈希里的 `$` 当作变量展开。后端启动时验证格式，留空则关闭管理入口。

`python3 scripts/set-admin-password.py --generate` 可生成本地初始密码。明文只保存到被 Git 忽略的 `backend/bin/admin-password.txt`，文件权限为 600，不打印到服务日志。手动设置新密码时移除该初始密码文件。修改后重启后端，旧看板会话立即失效。

密码正确后签发 32 字节随机令牌，固定 12 小时到期。`admin_sessions` 只保存令牌哈希和凭证版本摘要，每次管理请求都检查有效期与当前凭证版本。退出只撤销当前管理会话。聊天令牌不能访问管理接口，管理令牌也不能访问聊天接口。模型配置变更记录为共享“管理员”，日志保留管理会话 ID，不再声称能识别具体个人。

所有实例通过数据库共享登录限流，全局每分钟最多 10 次登录尝试，含成功与格式错误的请求。超过返回 429 和 `Retry-After: 60`。该共享密码入口不提供个人身份审计或多角色权限。

| 接口 | 内容 |
| --- | --- |
| `POST /admin/login` | 校验 `{password}` 并返回管理令牌 |
| `POST /admin/logout` | 撤销当前管理会话 |
| `GET /admin/me` | 当前共享管理员名称 |
| `GET /admin/snapshot` | 汇总、趋势、模型与工具分布、用户和选中用户的 Agent |
| `GET /admin/calls` | 单次模型请求日志 |
| `GET /admin/calls/{id}` | 按调用 ID 读取请求、响应 JSON，独立管理会话鉴权 |
| `GET /admin/timeline` | `user_id` 与 `agent`（`main` 或 Subagent UUID）的一页运行时间线；`before` 游标翻到更早，首页附带系统提示词 |
| `GET /admin/timeline/messages/{id}` | 单条消息的全文与截图，供时间线展开截断内容 |

时间是 RFC3339 UTC 半开区间，默认 24 小时、最大 31 天；列表每页最多 100。`agent` 需要同时指定 `user_id`，Main 用 `main`，Subagent 用 UUID。模型调用支持游标分页。快照使用只读 repeatable-read 事务；读请求有超时。未认证、过期或使用聊天令牌时返回 401，所有响应 no-store。

管理端默认 `127.0.0.1:5174`，服务端 `API_UPSTREAM` 默认 `http://127.0.0.1:8080`。原生 ES modules 与 Node 内置 HTTP，无第三方依赖或构建。`/api` 仅代理固定管理路径到固定上游，浏览器不持有数据库或供应商密钥。生产通过 HTTPS 反向代理独立部署；sessionStorage 只保留当前标签页会话。配额、封禁、删除用户、账单对账和角色管理不在本轮实现范围。

OpenRouter 可选模型实时读取 [OpenRouter 模型目录](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)。后端只返回名称、ID、上下文长度及目录价格，筛选支持工具调用与文本输出的模型。保存时重新检查所选渠道的目录，所选渠道目录不可用则不保存。目录能力不保证账户额度、供应商即时可用性或任务上下文容量，实际请求结果仍记录在调用日志。显示的目录价格是估算，实际费用以请求返回用量为准。ikun Gemini 使用下述独立目录。

| 接口 | 行为 |
| --- | --- |
| `GET /admin/model-settings` | 当前选择、生效 Subagent 模型、版本、来源和最后修改者 |
| `GET /admin/models` | 已配置渠道的模型候选目录，以及渠道未配置或目录请求失败的提示 |
| `PUT /admin/model-settings` | 原子保存 `main_model`、可空 `subagent_model` 与预期 `version`；冲突返回 409 |

三个接口均使用独立管理会话与 no-store。管理端同源代理只允许上述固定路径和方法，模型服务密钥始终只在 Go 后端。页面不会自动刷新覆盖尚未保存的选择。

## ikun Gemini（2026-10-30）

## 服务凭证管理（2026-10-30）

用户提出“我希望能在看板管理所有apikey”，确认采用加密存储、完整 Key 不回显、修改从下一次请求生效的方案，并明确“只有一个管理员”。服务配置不新增多管理员的并发保存协议或角色系统。页面管理整个部署共用的六组服务：OpenRouter、ikun Gemini、Resend、Serper、Parallel、EveryInfra。Resend 同时保存发件人，其他服务只需填写 Key。

默认地址已在隔离后端验证：只提交 Key 即可保存，旧空地址读取补默认值，旧环境变量仅有 Key 时也能导入。In-App Browser 已完成只填 Key 的页面保存验收。本地 Gemini 地址已保存为用户指定值，原 Key 保持不变。

选择理由是让企业 fork 后先配置管理员与基础设施，再在看板补齐业务服务。缺少供应商 Key 不再阻止后端启动。管理员身份、数据库连接与加密主密钥仍由部署端配置，聊天邮箱登录不承担首次配置职责。

`00015` 新增 `service_settings`。API Key 使用 Go 标准库 AES-256-GCM 加密，随机 nonce 与认证标签随密文保存，并以服务名称作为附加认证数据，密文不能在不同服务间互换。`SERVICE_ENCRYPTION_KEY` 是 Base64 编码的 32 字节主密钥，dev 与 prod 均必填，用 `openssl rand -base64 32` 生成。它不进入数据库，不能用管理员密码代替，也不能在已有密文后随意重新生成。数据库备份与原主密钥都需要保留，丢失主密钥后只能重新输入各供应商 Key。

看板只返回配置状态、末尾四位、配套字段和更新时间。“已保存 · 未验证”不表示供应商权限、额度或即时可用性已经验证。新 Key 只用于当次提交，不保存在浏览器持久存储中，提交结束后清空输入框。单条凭证无法解密时显示“无法解密”，管理员仍可替换或清除。

| 接口 | 行为 |
| --- | --- |
| `GET /admin/services` | 返回六组服务的脱敏状态，绝不返回密文或完整 Key |
| `PUT /admin/services/{service}` | 保存单个服务。`api_key` 省略或 null 保留原值，空字符串清除，非空替换。`base_url`、`email_from` 省略时保留 |

两个接口使用已有独立管理会话并返回 no-store。管理端代理仅开放固定六个服务路径。更改日志只记录服务名称、操作及管理会话 ID，不记录提交正文。保存不发模型请求或测试邮件，供应商拒绝凭证时由实际请求返回错误并记录原有调用结果。

模型目录、Main、Subagent、压缩、邮件和联网工具均在准备供应商请求时读取数据库，没有凭证缓存。已取到凭证的进行中请求继续完成，随后准备的请求读取新值。数据库读写失败或解密失败时返回错误，不使用旧环境变量兜底。清除操作保留空记录，后续使用该服务时报未配置。

## 自动压缩配置（2026-10-26，开发中）

“模型配置”页新增距上次回答的小时数与上下文 Token 阈值，默认分别为 6 和 200,000。前者接受 1–8760 的整数，后者接受 1000–2000000 的整数。两个值与模型选择一起保存到 `model_settings`，沿用版本冲突校验，重启后保留。满足任意条件，在下一次有任务、调用模型前检查并压缩，空闲期间不发摘要请求。

模型调用列表增加用途，区分 Agent 推理与上下文压缩。压缩详情显示原因、压缩前 Token（上一次同模型成功请求的官方 `prompt_tokens`）和覆盖序号，实际输入输出用量与费用仍取供应商响应；压缩后的大小即下一次 Agent 请求的官方用量，在那条调用中查看。旧历史不删除，摘要不进入用户聊天消息流。触发与恢复规则见 [02](02-data-model.md#自动压缩触发2026-10-26开发中)。
